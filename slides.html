Problem framing · language-to-evidence gap

Product claims are English.
Evidence lives in code.

The difficult step is not only searching a repository. It is turning an ambiguous business claim into the right technical questions.

Why templates do not scale

  1. 01Known claim types work — templates turn “AI search” or “secure export” into explicit source and test requirements.
  2. 02Arbitrary language does not — “secure,” “fast,” or “collaborative” mean different technical evidence in different architectures.
  3. 03The safe failure is useful — a generic scan can say “insufficient evidence,” but cannot responsibly infer the missing checks by itself.
Thesis

AI becomes meaningful at this translation boundary: it can propose a structured evidence plan, while deterministic code checks keep the result grounded.

Before AI: one prebuilt template per claim type. With AI: a constrained plan for unfamiliar claims.

Solution design · constrained AI augmentation

AI writes the evidence plan.
Software verifies it. Humans decide.

This is an augmentation loop, not a chatbot that declares a product claim true.

Target evidence loop

  1. 01INPUTAny product claim + local folder or public GitHub URL
  2. 02AI PLANSchema-constrained requirements, search concepts, uncertainty, and runtime questions
  3. 03VERIFYDeterministic source checks + optional reviewer-selected test/build
  4. 04DECISIONHuman review and accountability
Guardrail

AI may propose a plan or explain resolved citations. It cannot invent evidence, run arbitrary commands, or set the verdict.

What is real today · what AI adds next

The prototype proves the verifier, then exposes the AI opportunity.

Working now: evidence engine

Local/public-GitHub scans cite code, identify gaps, record history, and run one declared build or test with explicit review.

AI next: interpretation

Translate unfamiliar English claims into a typed evidence plan instead of requiring a new hand-authored template.

AI next: explanation

Summarise only cited source and execution evidence; surface ambiguity and questions for the reviewer.

Still human: product judgment

Security, production behaviour, claim wording, and investment decisions remain review decisions, not model outputs.
